# P8: Agente AI (chat guiado) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrar el Agente AI del sistema original (chat guiado paso a paso para crear Partes+Variantes, Entidades y BOMs) a la API Hono + frontend Next.js, con persistencia en `agent_conversations`/`agent_messages` y consultas generales vía Ollama Cloud (si hay API key).

**Architecture:** API Hono con endpoints REST. Estado de conversación guiado en memoria (Map con TTL 30 min — serverless sin Valkey). Flujos guiados 100% deterministas (sin IA): PromptBuilder portado a TS. `general_query` usa Ollama Cloud (OpenAI-compatible) si hay `AGENT_AI_API_KEY`; si no, responde offline. Frontend: página `/agent` con chat UI (burbujas, chips de sugerencias, campos con lookup).

**Tech Stack:** Hono 4.13.7, Next.js 16.3.4, supabase-js, zod 4.

## Global Constraints

- API base: `https://api.mimrp.com.ar`. Auth: `getSession()` + `apiFetch(path, token)`.
- NUNCA pasar funciones inline de Server Components a Client Components.
- Tablas: `agent_conversations` (company_id, tenant_id, user_id, intent, status, metadata jsonb), `agent_messages` (company_id, conversation_id, role, content, metadata jsonb), `agent_ai_logs`.
- `user_id`/`tenant_id` son bigint legacy — usar company_id como tenant_id.
- Estado guiado: `{ intent, data, step, _phase, _current_variante, variantes[], _current_component, components[] }`.
- Flujos guiados: create_part (11 campos parte + 9 variante + bucle otra variante), create_supplier (6 campos), create_bom (padre + componentes × N).
- Lookups: tipos_partes, grupos_partes, unidades_medida, estados_variante, tipos_entidad.
- Commits frecuentes, conventional commits.

**Files:**
- Create: `api/src/routes/agent.ts` + test
- Modify: `api/src/index.ts`

**Interfaces:**
- Produces:
  - `POST /api/v1/agent/message` body `{ conversation_id?, message, intent?, field_value?, field_label? }` → `{ data: { conversation_id, status, message, data, suggestions, guided_state } }`
  - `POST /api/v1/agent/confirm` body `{ conversation_id, data, intent }` → `{ data: { success, message, data } }`
  - `POST /api/v1/agent/cancel` body `{ conversation_id }` → `{ data: { success } }`
  - `GET /api/v1/agent/suggestions` → `{ data: [{ intent, label, description, icon, offline_safe }] }`
  - `GET /api/v1/agent/lookup/:type` → `{ data: [{ value, label }] }` (tipos_partes, grupos_partes, unidades_medida, estados_variante, tipos_entidad)
  - `GET /api/v1/agent/status` → `{ data: { isOnline, configValid, apiResponds, mode } }`
